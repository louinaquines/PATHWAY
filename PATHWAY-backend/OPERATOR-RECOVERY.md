# Free isolated backup and recovery

Current acceptance summary: PHASE8-ACCEPTANCE.md (October 12, 2026) supersedes historical pending statements below. The scoped real Auth restore/sign-in test passed by operator-reported private output. Final downloaded-archive emulator regression and fourteen focused tests passed. Full production recovery remains open; do not interpret this runbook as production sign-off.

This tool packages existing Firebase **emulator** Auth/Firestore exports. It is not a production export, production restore, managed backup, or point-in-time recovery service. Production project IDs are refused. The manuscript is unchanged.

## Operator procedure

1. Stop synthetic writes before exporting to obtain a consistent rehearsal snapshot. Run the existing `npm run emulator:backup` while the demo emulators are available. Check export success; never replace a previous backup with a failed export.
2. Supply a strong unique secret through `PATHWAY_BACKUP_SECRET` using a protected interactive environment, not a command-line argument, source file, chat, or committed `.env`. Store the key separately in a password manager. Windows file modes alone do not establish restrictive ACLs; use an operator-only directory with verified ACLs.
3. Run `node operatorBackup.js pack <snapshot-directory> <new-backup-file>` from the backend directory. Destination must not exist. AES-256-GCM authenticates the encrypted manifest/content; scrypt derives the encryption key. Each file has a SHA-256 checksum. Limits: 128 MiB of source files and 10,000 files; this is an in-memory pilot tool.
4. Copy the encrypted file to a second protected location. Run `node operatorBackup.js inspect <backup-file>` with the separately held key. Keep at least three successful versions; review retention manually. The tool never automatically deletes backups.
5. Set `PATHWAY_RESTORE_PROJECT=demo-pathway-security`. Run `node operatorBackup.js restore <backup-file> <new-isolated-directory>` for a no-write dry run. Review the target, then repeat with `--apply`. Existing destinations and symlink ancestors are refused. A failed restore retains its partial target and reports progress; never import or retry that directory. Choose a new isolated directory after resolving the cause.
6. Import the recovered export only into dedicated demo emulators, then compare Auth IDs, student/company relationships and attendance records. `node security-tests/emulator-restore-qa.js --encrypted` runs the current saved snapshot through encryption, dry-run, readback checks and dedicated Auth/Firestore emulator import. Its random rehearsal key is ephemeral; the temporary archive is not a durable backup.
7. Remove the secret from the environment after use. Do not commit archives, decrypted snapshots, account exports or keys.

### Scoped acquisition and link-recovery planning

`attachmentRecovery.js` provides an adapter-based operator core, not a production download command. Its authorized `readRecord`, `readMetadata`, and `downloadBytes` adapters must restrict access to explicitly selected records/assets. Download adapters must enforce streaming byte/time limits and refuse redirects; the core rejects unexpected byte counts and checks provider metadata and source record identities before and after acquisition. It never fetches arbitrary attachment URLs. Local staging is sensitive plaintext and requires verified operator-only ACLs; only the subsequent encrypted archive is a backup.

An incomplete acquisition preserves staged files, reports completed count, and never publishes a complete `acquisition.json`. Do not use partial output as a complete backup. Reconciliation is dry-run only: restored bytes must match their checksum, source document/version and original asset ID. A replacement must have a separate identity and independently verified byte checksum. No provider upload or database update is implemented here. Live provider adapters, fresh-upload readback and transactional link replacement are still acceptance-open; do not substitute caller-supplied checksum claims for provider readback.

`node --test security-tests/attachment-recovery.test.js security-tests/operator-backup.test.js` exercises loopback HTTP acquisition of the existing TEST ONLY PDF, encryption/restoration, and dry-run mapping; negative cases cover authorization failure, stale provider/source records, truncation, changed original asset, corrupt bytes and partial acquisition.
